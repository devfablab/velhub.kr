### 작업: 블로거 공동 집필 글

정해진 것
- 1인 블로그 운영자 2명만. 팀 블로그 불가. 3명 이상 불가
- 글은 하나만 존재하고 두 블로그 모두에 보임
- 공동 집필 부분만 다르고 나머지(게시판, 카테고리, 댓글, 좋아요, 조회수, 구독, 수익)는 기존 블로그 글 규칙 그대로
- 수익은 나누지 않음. 각 블로그는 자기 규칙·자기 수익 그대로
- 편집: 편집 잠금 + 변경점 보기 (아래 참고)
- 턴제 사용 안 함
- 공개: 두 사람이 "공개 가능"에 합의 → 이후 협의해서 공개 일시 정함
- 발행 후 수정·숨김도 둘이 합의 (삭제 기능 없음, 데브허브 기본 정책)
- 한쪽이 폐쇄·탈퇴해도 남은 쪽에 글 유지. 떠난 쪽에서만 안 보임
- 초대: 상대 운영자 이름(블로그 정보에 나오는 이름: 별명, 없으면 활동명)으로 검색 → 결과에 사이트 주소, 블로그 이름, 운영자 이름 3개 표시 → 골라서 초대 → 상대가 알림에서 수락하면 시작

- 기존 글 구조(테이블·게시판·카테고리·연재·공개 범위·검색 노출) 그대로 유지. 공동 집필 때문에 갈아엎지 않음
- 작성자 표기: 두 사람 모두, 초대한 사람이 먼저
- 검색 노출: 두 블로그 모두 그대로 노출 (대표 주소 지정 안 함)
- 공동 집필 글 전용 채팅 (에디터와 별개, 둘이 협의용). 보관 무제한, 욕설 필터 없음, 본인 메시지만 지움 + 지운 건 둘 다에게 "삭제된 메시지입니다" 표시. 커뮤니티 채팅에는 적용 안 함. 메시지는 Supabase(co_post_messages)에 저장, Cloudflare(CoPostRoom)는 실시간 전달만
- 공개: "공개 협의 요청" 버튼에 공개 일시를 같이 담아 보냄 → 알림 → 상대 수락 시 합의. 둘 다 요청 버튼을 누르면 합의로 처리. 공개 합의와 공개 일시는 분리하지 않음
- 공개 전 한쪽이 중단하길 원하면 그냥 둠 (별도 처리 없음)
- 삭제(시스템상 비공개) 요청: 알림으로 상대 동의 받음
- 공개된 글 수정: 공개본은 그대로 두고 수정본에서 같이 고친 뒤 합의하면 반영
- 요청에 응답 없어도 자동 거절·만료 없음
- 신고로 숨겨지면 두 블로그 모두 같이 처리
- 알림: 초대, 수락·거절, 공개 협의(공개 일시 포함), 수정·삭제 요청과 결과
- 에디터: 기존 Toast 에디터 유지 (실시간 공동 편집 안 함, 에디터 교체 안 함)
- 편집 잠금: 한 사람이 수정 페이지에 있으면 상대는 수정 불가. "상대가 수정 중입니다. 채팅으로 상의하세요" 표시
- 잠금 풀림: 수정 페이지를 닫으면 바로 풀림. 열어 둔 채 30분 동안 활동이 없으면 임시 저장 후 풀림. 활동 = 잠금을 가진 사람의 에디터 입력 또는 채팅 메시지 전송 (하면 30분 다시 시작)
- 변경점 보기: 내가 마지막으로 작업한 이후 상대가 수정한 내용이 있으면 에디터 위에 "변경점 보기" 표시. 그 사이 수정을 모두 합쳐서 한 번에 마크 처리해서 보여줌 (목록 아님). 에디터에는 이미 최신 내용이 들어가 있음. 양쪽 모두 같은 방식

- 공개 일시 변경: "일시 변경" 버튼 → 상대에게 동의 알림 → 합의될 때까지 반복. 변경이 합의되기 전에 마지막으로 합의된 시간이 되면 그 시간에 공개
- 둘 다 공개 협의 요청을 눌렀는데 일시가 다르면 합의 안 된 상태 → 일시 변경으로 맞춤
- 동시에 진행하는 공동 집필 수 제한 없음
- 블로그는 게시판이 하나. 글은 초대한 사람(A) 블로그 글로 생성. 초대받은 사람(B)은 수락할 때 자기 블로그의 카테고리·연재를 선택 (둘 다 선택 안 해도 됨)
- 공개 범위는 각 블로그에서 고른 연재에 따라 기존 규칙대로 자동 적용
- 공동 집필 글은 해시태그 사용 불가
- 별도 탭·게시판 없음. 기존 글 목록에 같이 나옴 (B 목록에도 getPostList에서 포함, B의 게시판·연재 기준). 받은 초대·보낸 초대는 관리 화면 글 목록 위에 표시
- 공동 집필 글을 열면(관리 수정·글 보기) 공동 집필용 처리 필요: 3단계·8단계
